# WhatBin server

Run from the repository root with Node.js 22 or later. On a fresh checkout, copy `app/.env.example` to `app/.env` and fill in the credentials; `app/.env` is Git-ignored.

```sh
node --env-file=app/.env app/server.mjs
```

Recognition uses Gemini 3.7 Flash, on-demand explanations use Gemini 3.6 Flash, and source research uses Gemini 3.8 Flash through the Interactions API. Explanations use Vercel AI SDK `streamText`, `@ai-sdk/google`, and `@ai-sdk/mcp`, with read-only Sanity Context tools. Set `GEMINI_API_KEY` server-side; explanation also requires `SANITY_CONTEXT_MCP_URL` and an organization-level Context Viewer token in `SANITY_API_READ_TOKEN`. These endpoints return HTTP 503 when required configuration is missing.

Run app regression tests from the repository root with `node --test app/server.test.mjs app/source-research.test.mjs`.

## API

- `POST /api/recognize` accepts JSON with at least one of a description and image: `{"description":"an old mattress"}`, `{"description":"a discarded mobile phone"}`, `{"description":"an intact used AA battery"}`, `{"description":"a standalone used rechargeable lithium-ion battery"}`, `{"description":"a complete used power bank"}`, `{"description":"a used fluorescent tube, already broken"}`, `{"description":"a used mercury thermometer"}`, `{"image":{"mimeType":"image/jpeg","base64":"…"}}`, or `{"description":"a used fluorescent tube","image":{"mimeType":"image/jpeg","base64":"…"}}`. If both are supplied, recognition considers both. Supported image types are JPEG, PNG, and WebP. Recognition proposes old mattresses, clearly identified discarded intact household-size AA/AAA batteries, standalone rechargeable Li-ion batteries (not installed in a device or contained in a power bank), clearly identified used fluorescent lamps or tubes including broken tubes, household mercury thermometers including broken thermometers, and Hanoi-only discarded mobile phones; the user must confirm the recognized item. Recognition does not select disposal guidance.
- `POST /api/resolve` accepts a confirmed candidate, for example `{"jurisdiction":"hanoi","canonicalItemId":"used-fluorescent-lamp","confirmed":true}` or `{"jurisdiction":"hanoi","canonicalItemId":"used-lithium-ion-battery","confirmed":true}`. Shared lamp, thermometer, standalone Li-ion battery, and phone item IDs/names are exactly `used-fluorescent-lamp` / `Used fluorescent lamp`, `used-mercury-thermometer` / `Used mercury thermometer`, `used-lithium-ion-battery` / `Used rechargeable lithium-ion battery`, and `used-mobile-phone` / `Used mobile phone`; their Sanity rule IDs are maintained with the published rules when published. `used-mobile-phone` has no published rule, so resolution remains `UNKNOWN` (including Hanoi) until a reviewed rule is published. `used-power-bank` / `Used power bank` has no published Sanity rule and resolves `UNKNOWN` in either city. Existing old-mattress and AA/AAA battery rule IDs remain distinct from their shared canonical item IDs.
- `POST /api/explain` accepts a confirmed result, question, and optional page-local history, for example `{"jurisdiction":"hanoi","canonicalItemId":"old-mattress","question":"Why is this the result?","history":[],"confirmed":true}`. The server re-resolves the selected city and the other city for the same item, then streams plain-text answer chunks. The UI displays verified source links from the resolver, never model-generated URLs. City comparison is allowed only when both results are `MATCHED`; `UNKNOWN` and `CONFLICT` permit no disposal route. History is bounded to 10 messages and is not stored.
- `POST /api/research-source` accepts supported existing canonical item/jurisdiction pairs. `used-mobile-phone` / `Used mobile phone` is Hanoi-only and returns a transient preview or gap; no phone rule is published, and no Ho Chi Minh City phone source was verified. Source research never writes Sanity. The endpoint requires an allowed `Origin` from `SANITY_STUDIO_ORIGINS` and a Studio bearer token verified through the Sanity Access API.

The server limits request bodies and does not retain or log descriptions, photos, questions, or chat history. Photos are sent to Google's Gemini service for recognition; explanation questions and bounded page-local history are sent to Gemini, which can make read-only calls through the configured Sanity Context MCP endpoint. Do not submit sensitive data. Keep both credentials server-side. Set `SANITY_CONTEXT_MCP_URL` to the HTTPS Sanity Context endpoint on `api.sanity.io` and `SANITY_API_READ_TOKEN` to an organization-level Context Viewer token; the server rejects non-Sanity hosts and non-HTTPS URLs before forwarding the token. The endpoint must expose `initial_context` and a content reader such as `knowledge_base_read`, `groq_query`, or `array_field_reader`; the server passes the configured read-only tool set to the model. The agent explains only server-resolved WhatBin outcomes and never selects an action. Rule lookup is an anonymous published Sanity query. Source research is limited to an exact `Origin` listed in `SANITY_STUDIO_ORIGINS` and a Studio bearer token verified by the Sanity Access API; tokens are never logged or persisted. Research returns only a transient preview or gap and never writes Sanity documents. Editors must create an unpublished draft explicitly, then follow normal review and publication. Runtime resolution reads published rules and conflict records from Sanity. `app/knowledge-base.json` remains only as migration input and is not read at runtime.

The Hanoi phone research candidate references the official [Decision 87/2025/QĐ-UBND city record](https://vanban.hanoi.gov.vn/chi-tiet-van-ban/ve-viec-quy-dinh-quan-ly-chat-thai-ran-sinh-hoat-cua-ho-gia-dinh-ca-nhan-tren-dia-ban-thanh-pho-ha--231176) and [official attachment](https://datafiles.hanoi.gov.vn/gov-hni/6847/VanBan/2026/1/6/Q%C4%90PQ-UBND-87-2025.pdf), Articles 5(1)(h) and 7(2)(a); Article 7(1)(a) makes urban collection time/place dependent on commune directions. **Unpublished review wording (Article 7(2)(a)):** Keep the discarded phone separate in its own bag; transfer it to an organization or person for reuse or recycling, or to the household waste collection service. Alternatively, store it at home and periodically take it to the commune-designated central collection point. Do not infer an exact point, schedule, or fee. The attachment's internal number/date/effective-date fields are blank; portal metadata provides instrument identity and currentness details. This is a research candidate only, not approved or published. Complete power banks remain `UNKNOWN`; no power-bank coverage was added.

Thermometer coverage is limited to clearly identified discarded household mercury thermometers; digital/electronic or non-mercury thermometers, industrial instruments, and uncertain types are unsupported. Hanoi requires safe, corrosion- and water-resistant, non-leaking packaging and permits home storage or scheduled collection, but its cited decision gives no mercury-thermometer-specific broken-item or cleanup instruction. Ho Chi Minh City says not to break mercury thermometers; if one is broken, retain it safely to avoid injury and mercury dispersal during sorting, collection, and treatment. Neither city's cited rule provides a cleanup procedure.

Hanoi Decision 87/2025/QĐ-UBND (effective 2026-01-08) and Ho Chi Minh City Decision 58/2025/QĐ-UBND (effective 2025-04-25) apply their general discarded-battery/accumulator hazardous-waste rules to standalone Li-ion batteries. Hanoi requires safe, corrosion- and water-resistant, non-leaking packaging and allows home storage or periodic local collection without a service fee. Ho Chi Minh City requires the battery to remain intact (do not dismantle), hazardous waste to be kept separate and safe, and transfer to a licensed operator or local designated point; no fee applies only at a compliant point. These current city decisions do not establish a general route for intact power banks. An official [2023 Ministry of Agriculture and Environment report](https://vea.mae.gov.vn/tin-tuc-su-kien/8192/lan-toa-tinh-than-bao-ve-moi-truong) describes local Hanoi “Nhà của pin” programs collecting old batteries and broken power banks, but this dated report does not establish current citywide acceptance. `used-power-bank` / `Used power bank` has no published Sanity rule and resolves `UNKNOWN` in both cities.

## Vercel

Import the repository and set the Vercel project root directory to `app`. Vercel uses `server.mjs` as the Node.js server entrypoint and includes static assets in the server bundle.

Set `GEMINI_API_KEY`, `SANITY_CONTEXT_MCP_URL`, `SANITY_API_READ_TOKEN`, and `SANITY_STUDIO_ORIGINS` in Vercel project Environment Variables. Use an organization-level Context Viewer token; the endpoint must expose `initial_context` and a content reader (`knowledge_base_read`, `groq_query`, or `array_field_reader`). The origins value is a comma-separated list of exact Studio origins. Do not commit secrets. Run `vercel dev` from `app/` to verify locally, or `vercel` for a preview deployment. Do not use `vercel --prod` without production approval.
